# Process

> (`docs.process.guide` in `sdlc.py config`). Each block here, a heading or a `- **lead**`
> bullet, stands in for the guide's block of the same heading path, or lead, when it holds text of
> its own, and is read after its parent's block there when the guide has none like it. A heading
> with nothing under it only places what follows. Copy any block of the guide here to change it

## The point of the process

### The failure it stops

A wrong boundary file reaching the people who render it: an area missing from, doubled in, or
filed under the wrong parent, or a file moved out from under a URL someone hotlinks.

The files are generated by scripts and committed by the thousand, so a fix arrives as a diff no one
can read: a municipality filed under the wrong province (Davao City in Davao del Sur) or a district
with none of its municipalities (NCR) looks like any other change to coordinates. Users find it
after they have drawn the map. Everything below exists to put a checkable claim between a change
and the people who rely on it.

## Tiers: the overhead control

### Always Tier 2, whatever the size of the diff

- **Re-running a generation script over a level.** One command, but it rewrites every file of that
  level for everyone using that vintage, and the diff is too large to review by eye. The spec names the
  PSGC codes that should change, and verification proves only those did.
- **A new vintage directory** (`<year>/`). It is where every new user starts, and its layout
  becomes public API the day it is pushed.

## Where a change is worked: one worktree per change

### What a worktree needs

A fresh worktree has no source shapefiles: they are gitignored, and the generation scripts fetch
them on their first run (`scripts/fetch-shapefiles.sh`, from a local
`philippines-psgc-shapefiles` checkout or the
[faeldon/philippines-psgc-shapefiles](https://github.com/faeldon/philippines-psgc-shapefiles)
release, about 700 MB per quarter). A change that regenerates needs `gdal` and `mapshaper`
installed. `commands.worktree_setup` is unset because most changes don't regenerate.

## Running the stages

### Stage 1 — Plan → `/sdlc:intent`

#### Push-backs at Stage 1

A data-error report becomes an intent that names the PSGC codes involved and the parent each
belongs under in the PSA's PSGC release. "Fix Davao" is not an intent; one that says which area
(its code), which file it is in now, and which file it belongs in is.

### Stage 4 — Test

#### The gate and the slower check

The gate (`commands.check`) parses every JSON file under `latest/` with `jq`, and fails if
anything not ignored, tracked or untracked, sits under a build directory (`<quarter>/`), `dist/`,
`scripts/20*`, or any `hires/`: only `latest/`'s medres and lowres are committed. It also fails
if any commit on `HEAD` carries a `Co-Authored-By: Claude` trailer (017). There is no slower check: regenerating needs the source
shapefiles, `gdal` and `mapshaper`, and the scripts `rm -rf` their output first. So a change that
regenerates proves its codes in `checks.md`: for example, a `jq` check that a municipality's
code appears in its parent's file and in no other file at that level.

### Stage 5 — Ship → `/sdlc:ship`

#### The path to users

Pushing `master` is publishing: users hotlink `raw.githubusercontent.com/.../master/latest/...`,
so a file under `latest/` is live the moment the push lands, release or not. `/sdlc:release`
bumps `latest/manifest.json`'s version and builds the quarter's assets into `dist/<tag>/`;
`/sdlc:publish` pushes `master` and the tag and uploads them as the GitHub release, which is
never replaced once it is up.

### Stage 6 — Maintain → `/sdlc:health`

#### What the scans watch

No scans yet: `commands.scan` is unset. The obvious first one checks the hierarchy the bugs
broke: every feature in a child file carries its parent's code (`adm1_psgc`, `adm2_psgc`, …), and
that code should be the one in the file's name.
