# 013 — Publish PSGC 3Q 2026 as v1.0.0, with latest/ in the tree and every quarter as a release · spec

> Tier 2 only. Reads from intent.md; read by plan.md. If you can't write a testable requirement
> list, the intent isn't understood yet — go back to Stage 1 rather than designing around the fog.

## Requirements

1. **R1. Scripts build any quarter.** Each `scripts/topojson-*.sh` takes the release tag and quarter
   as arguments (`topojson-regions.sh v1.0.0 2026-3q`), fetches with
   `fetch-shapefiles.sh <tag> <quarter>`, and writes `<quarter>/{geojson,topojson}/<level>/<res>/`
   at the repo root. No script hard-codes a vintage; run with no arguments, each prints its usage
   and exits non-zero.
2. **R2. Build directories are never committed.** `.gitignore` ignores `/[0-9][0-9][0-9][0-9]-[1-4]q/`
   and `/dist/`; the gate fails if `git ls-files` lists anything under them.
3. **R3. 3Q 2026 builds clean.** `2026-3q/` built from `v1.0.0` holds 18 `regions/` files,
   88 `provdists/` and 1,642 `municities/` files per format and resolution, every coordinate in
   WGS84 (lon 114–128, lat 4–22), and no `geometry: null`.
4. **R4. Hierarchy holds.** In `2026-3q/` lowres GeoJSON, every feature's parent code equals its
   file's, and each file's ids are exactly the release's children of that parent with a shape
   (standard `PH_Adm4_BgySubMuns`, `geom_src <> 'none'`). Checked as 012's R9 was, against
   `scripts/processed/2026-3q/*.csv`.
5. **R5. One distribution in the tree: `latest/`.** `latest/` holds the newest quarter's
   **medres and lowres**, GeoJSON and TopoJSON, in `2023/`'s layout and names
   (`latest/geojson/provdists/lowres/municities-provdist-1804500000.0.001.json`). No `hires/`
   directory is committed anywhere.
6. **R6. `latest/` says what it is.** `latest/manifest.json` holds `version`, the PSGC quarter
   (`2026-3q`), the source release (`faeldon/philippines-psgc-shapefiles` `v1.0.0`) and the
   date built; it is the file `release.version_files` names.
7. **R7. Old vintages leave the tree.** `2011/`, `2019/` and `2023/` are removed in this change. Each
   is first published as a release of this repo (R10), built from history with `git archive`, so
   its bytes are exactly what `master` held: `2023/` as of 012's commit `195f6db2`.
8. **R8. Releases carry every quarter in full.** `release.prepare` builds into ignored `dist/<tag>/`:
   one zip per format and resolution (`geojson-hires.zip` … `topojson-lowres.zip`), hires
   included, and a `SHA256SUMS` over them; it changes no tracked file. `release.publish` uploads
   them with `gh release create <tag> … --notes-file`, non-interactively, and refuses if the tag's
   release already exists.
9. **R9. v1.0.0 is 3Q 2026.** `release.version_files = ["latest/manifest.json"]`, `tag =
   "v{version}"`; `/sdlc:release 1.0.0` then `/sdlc:publish` produce release `v1.0.0` whose notes
   name PSGC 3Q 2026 and the source release `v1.0.0`.
10. **R10. Legacy releases.** Tags `2023-4q`, `2019` and `2011` exist as releases with their
    vintage's zips and `SHA256SUMS`, built by `scripts/release-legacy.sh <tag> <dir> <ref>`. They
    are created behind their own approval before the push that removes the directories, and the
    script refuses a tag whose release already exists.
11. **R11. Renamed paths are listed.** The v1.0.0 notes list every `latest/` path that has no
    counterpart under `2023/`'s name and vice versa: 1 region file added (`1800000000`), 4
    `provdists/` renamed (Negros ×3, Sulu), 82 `municities/` renamed. Generated by a script from
    the two file lists, not by hand.
12. **R12. Barangays from the standard file.** Built from `PH_Adm4_BgySubMuns` (not `_complete`);
    the 18 shapeless rows are left out; `geom_src` is kept and the README says what `plotted` and
    `dissolved` mean.
13. **R13. The gate covers what is published.** `commands.check` parses every JSON under
    `latest/`, fails on tracked files under build directories, `dist/`, or `scripts/20*`, and no
    longer names `2023/`.
14. **R14. README matches the new layout.** It points at `latest/` (demo link, tree, levels), says
    medres and lowres are in the tree and hires is in each release, links the releases (latest,
    `2023-4q`, `2019`, `2011`), says that `2011/`, `2019/` and `2023/` moved there, and states
    the projection correctly: WGS84 lon/lat (EPSG:4326), reprojected from the source's EPSG:32651
    (nit 012-1).
15. **R15. Invariants say what is stable now.** `AGENTS.md`'s invariants are rewritten (Contracts
    touched, below), and its commands and "how the files are made" describe the quarter
    arguments, `latest/`, and the release steps.

## Design

**Build.** The four scripts lose their `YEAR/TAG/QUARTER` header line for two positional arguments,
`TAG QUARTER`, and write `$ROOT/$QUARTER/...`. Everything else from 012 stays: fetch and verify,
`ogr2ogr -t_srs EPSG:4326`, `keep-shapes`, `geom_src <> 'none'`. `scripts/build-quarter.sh TAG
QUARTER` runs the four in order. Build directories (`2026-3q/`, and `2023-4q/` should anyone
rebuild 4Q 2023) are ignored.

**Publish to the tree.** `scripts/publish-latest.sh QUARTER` replaces `latest/` with the medres and
lowres directories of `$QUARTER/` (`rm -rf latest/geojson latest/topojson`, then copy) and writes
`latest/manifest.json`'s quarter, source and build date, leaving `version` for `/sdlc:release`.
It refuses a quarter whose build directory is incomplete (a level missing, or a file count off from
the release CSVs).

**Releases.** The release loop the plugin already has does the versioning: `version_files` is
`latest/manifest.json` (its one `"version": "X.Y.Z"` line), `tag = "v{version}"`,
`prepare = "scripts/release-assets.sh {tag}"`, `publish = "scripts/release-publish.sh {tag}"`.
`release-assets.sh` zips the quarter that `manifest.json` names, from its build directory (hires
included, which is why it builds from `<quarter>/`, not `latest/`), into `dist/{tag}/`, writes
`SHA256SUMS` and the notes (R11's list from `scripts/renamed-paths.sh`, the PSGC quarter, the
source release). `release-publish.sh` runs `gh release create {tag} dist/{tag}/* --title …
--notes-file dist/{tag}/notes.md`, and fails if the release exists.

A baseline is needed for `/sdlc:release` to count from: `latest/manifest.json` starts at
`"version": "0.0.0"`, tagged `v0.0.0` on the commit before this change's (the plan names the
exact step); `/sdlc:release 1.0.0` is then the deliberate 1.0 the plugin asks for.

**Legacy releases.** `scripts/release-legacy.sh TAG DIR REF` builds the same zips and `SHA256SUMS`
from `git archive REF -- DIR` (so it reads history, not the working tree, and works after the
directory is gone), and creates the release. Run three times (`2023-4q 2023 195f6db2`,
`2019 2019 <ref>`, `2011 2011 <ref>`) behind one approval, before the push that removes the
directories, so no hotlink is ever left without its release.

**Order of operations** (the plan details it): build 2026-3q → publish to `latest/` → remove
`2011/ 2019/ 2023/` → docs and gate → ship → close → legacy releases (approval) → `/sdlc:release
1.0.0` → `/sdlc:publish` (push + v1.0.0 release).

**What it costs.** `latest/` medres+lowres: ~23 MB packed of history per quarter (measured on
012's commit: geojson 4.2+10.8, topojson 3.3+4.8). Removing `2011/ 2019/ 2023/` shrinks the
checkout by ~1.7 GB but not clones: history keeps every version, including 012's ~111 MB.

## Contracts touched

**Two invariants change on purpose; this is the policy edit.** `AGENTS.md` today says:

- *Paths are public API* — every file name under `<year>/` is hotlinked; renaming or moving one is
  breaking.
- *Old vintages are frozen* — `2011/`, `2019/` never edited; a new release becomes a new `<year>/`.

This change removes `2011/`, `2019/` and `2023/` from the tree, which breaks every hotlink into
them, and it replaces "a new `<year>/`" with one moving `latest/`. Recorded as **`impact: major`**,
with the releases (R10) in place before the push and the README saying where each went. Rewritten:

- **Paths are public API.** `latest/`'s layout and naming are stable; a file name changes only when
  its PSGC code does, and every release's notes list those (R11). Each release's assets are
  immutable once published.
- **Vintages are releases.** Every PSGC quarter is a GitHub release of this repo with all
  resolutions and a `SHA256SUMS`; a published release is never replaced. Only the newest quarter
  is in the tree, at `latest/`, medres and lowres only.
- **The PSGC hierarchy holds** — unchanged; R4 checks it for 3Q 2026.
- **Output location and form** — generated files are committed only under `latest/`; build
  directories, `dist/` and source shapefiles never are. WGS84 lon/lat, 10%/1%/0.1% from one
  source, `keep-shapes` on every `-simplify`.

## Alternatives rejected

- **`2026-3q/` beside `2023/`, every quarter in the tree** (the intent as first written): ~111 MB
  of history per quarter, forever, in every clone.
- **Overwriting `2023/` in place:** keeps links working but serves 3Q 2026 under a name that says
  2023.
- **Keeping `2011/`, `2019/`, `2023/` frozen in the tree:** no link breaks, but the tree stays at
  ~1.7 GB and the repo carries three layouts.
- **All six sets in `latest/`:** hires GeoJSON alone is 69 MB of history per quarter.
- **Per-quarter tags (`psgc-2026-3q`)** for the current line: the plugin's release loop versions
  by semver, and a renamed path is a breaking change it should count.
- **`_complete` barangays:** replaces 4 surveyed barangays with approximations to fit 4 new ones.
- **A history rewrite** to shrink clones: breaks every clone and fork; not this change.

## Verification

- **Gate** passes (`latest/` parses; nothing tracked under build dirs, `dist/`, `scripts/20*`).
- **Build:** `scripts/build-quarter.sh v1.0.0 2026-3q` ends with output only under `2026-3q/`;
  `git status --short` shows nothing under it.
- **`checks.md`:** R1 (usage on no args), R3 (counts, WGS84, no nulls), R4 (hierarchy vs CSVs),
  R5 (no `hires/` tracked; `latest/` = medres+lowres of `2026-3q/` byte for byte), R6 (manifest
  fields), R7/R13 (no `2011/ 2019/ 2023/` tracked; gate names no year), R11 (renamed-path counts
  1/4/82).
- **Releases, dry run before any upload:** `release-assets.sh` and `release-legacy.sh --dry-run`
  produce zips whose `SHA256SUMS` verify, and whose unzipped contents equal the source tree
  (`diff -r` against `2026-3q/`, and against `git archive` output for each legacy ref).
- **After publish (manual, notes.md):** each release lists its assets; `curl -L` of one asset per
  release matches its `SHA256SUMS`.
